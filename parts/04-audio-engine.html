CHAPTER 04 · 引擎

空间音频引擎（官方 API 核对）

本章每一个 API 名与参数都来自本机 PICO SDK 6.1 的 agent-vault 官方文档（com.pico.spatial.core.ecs.audio / com.pico.spatial.audio），不是凭记忆写的。底层用 HRTF 渲染：「models the acoustic characteristics of the human ear based on HRTF」。

为什么这一章最重要 空间音频是核心 SDK 能力，不是实验性 API —— 不需要 pico.spatial.use_experimental_api，不要求 PICO OS 6，不依赖 SpatialML。 这意味着它的真机门槛比「拍照变山」那条路低得多（那条要 OS 6，4 Ultra 是 OS 5）。

4.1API 清单与参数

API包用途与关键参数
AudioResource.load(name, "asset://xxx.wav", LoadType.FROM_ASSETS) core.ecs.audio 从 assets 加载音频资源
ObjectAudioComponent core.ecs.audio 声源绑实体：volume（总音量）、Directivity(pattern, sharpness)（指向性）、distanceAttenuationMode（距离衰减）、reverbVolume（混响音量）。位置或朝向变化时自动调整输出
Directivity(pattern, sharpness) core.ecs.audio pattern = 0 全向 → 0.5 心形 → 1 八字形；sharpness = 聚焦程度。绕到柱背面声音变闷就是它，官方内建，不用自己做遮挡
DistanceAttenuationMode core.ecs.audio INVERSE_SQUARED（默认，按距离平方反比衰减）/ FIXED（恒定）。柱阵缩放时能听出变远变近
AmbientAudioComponent core.ecs.audio 环境床（房间底噪）—— 让「空间」听起来不空
ChannelAudioComponent core.ecs.audio 通道音（副窗反馈音等）
entity.prepareAudio(resource) / entity.playAudio(resource) core.ecs.audio 拿到 AudioPlayerController，控制 play() / pause() / stop()
AudioEvents core.ecs.audio 按播放时间点触发自定义回调 ⇒ 音画同步交给系统，不自己算进度
AudioMixerGroupsComponent + AudioMixerGroupResource.setVolume() core.ecs.audio 统一控制一组资源的音量 / 混响（做交叉淡入淡出、避免爆音）
AudioResourceLibraryComponent core.ecs.audio 以字典方式批量增删查 24 份资源
AudioGroupResource + AudioGroupResourcePlayMode core.ecs.audio 资源集合按播放模式随机选一个 —— 做「随机环境声」很好用
AudioResourceConfig(mixerGroupID, ambisonicsType, ...) core.ecs.audio 资源配置，含 AmbisonicsType（360° 音频）
SpatialAudioTrackExtension spatial.audio 给第三方播放器接空间音频：SpatialAudioMode.OBJECT / AMBIENT，支持 attachToEntity（绑 3D 物体）或 attachToContainer（绑窗口）

4.2核心代码骨架

柱子实体就是声源 —— ObjectAudioComponent 直接挂在柱子的 Entity 上。这样柱阵旋转 / 缩放时，声音位置自动跟着走，不需要任何额外同步代码。

// 柱子 = 声源 val column = Entity() column.components.set( ObjectAudioComponent( volume = 1.0f, Directivity(pattern = 0.35f, sharpness = 0.60f), distanceAttenuationMode = DistanceAttenuationMode.INVERSE_SQUARED, reverbVolume = 0.5f ) ) val player = column.prepareAudio(audioResource) // AudioPlayerController player.play()

官方文档给出的等价写法（第三方的 AudioTrack / ExoPlayer / MediaPlayer 也能接）：

val extension = SpatialAudioTrackExtension() extension.spatialAudioTrackExtensionConfig( mode = SpatialAudioMode.OBJECT, isAmbisonic = false, builder = audioTrackBuilder ) extension.attachToEntityWithBuilder(targetEntity, audioTrackBuilder) val audioTrack = audioTrackBuilder.build()

4.3声源策略

24 柱 = 24 个潜在声源但同时只激活能量最高的 4 个。理由有两条：一是性能（24 路空间化渲染 + 衰减计算）；二是听感清晰（同时响 24 个会糊成一片，评委反而听不出方向）。
声源实体即柱子ObjectAudioComponent 挂在柱 Entity 上 ⇒ 柱阵变换时声音位置自动跟随，无需同步代码。
资源统一管理24 段音频用 AudioResourceLibraryComponent 管理；播放头推进靠 AudioEvents。
切换要交叉淡化换声源时用 AudioMixerGroupResource.setVolume() 做淡入淡出，否则会出现爆音 —— 爆音在评委的耳朵里是致命的。
不做实时麦克风采集输入是文件回放。理由：模拟器无麦克风；回放可复现、可调试、可在提交包内自洽（不依赖任何授权）。
频段决定指向性低频柱 pattern 更全向（包裹感），高频柱 pattern 更聚焦（定位感）。零成本，但听起来立刻专业。
六维预估：声之建筑 vs 曝光暗房
声之建筑的优势集中在「创新」与「交互体验」两维 —— 前者来自独占空间音频硬指标，后者来自评委可亲身参与。
官方样例工程是最快的启动路径 官方「Create immersive spatial audio」样例的完整结构是：DefaultStage + Planar 控制面板 + 环境音 + 移动声源，源码在 app/src/main/java/com/pico/spatial/sample/spatialaudio/： Main.kt（声明 Stage 与控制面板）/ ui/ImmersiveScene.kt / ui/AudioControlViewModel.kt / data/AudioResourceStore.kt / manager/AudioPlayer.kt / ecs/FlyTrajectory.kt。
