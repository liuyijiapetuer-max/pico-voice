官方空间音频 API 与 Stage 配置速查表

下面这张表是执行期最常翻的一页：每一行都对着官方 SDK 6.1 agent-vault 文档逐条核对过，可以直接照着写，不需要再去翻文档。空间音频属于核心 SDK 能力，不需要实验标志，也不依赖 PICO OS 6（那条要求只针对 SpatialML）。

API / 组件类别关键参数在本方案里的位置
ObjectAudioComponent组件挂在 Entity 上柱阵即声源 —— 柱子动了声音自动跟着走，不写同步代码
Directivity(pattern, sharpness)参数逐柱指向性指向层：「绕到柱背声音变闷」—— 最省力也最难反驳的证据
reverbVolume参数混响强度混响层：同一段声音换个混响，就是换了个房间
AudioEventsAPI按播放时间点回调音画同步：柱高、光环、当前播放位置全部对齐
AudioResource.load(…)API加载音频资源60 秒母带切成 24 片，24 根柱子各挂一段
entity.prepareAudioAPI预加载开场前先备好 —— 播第一句时不卡，这是第一印象
AmbientAudioComponent组件环境音房间底噪：让空间听起来不空
ChannelAudioComponent组件通道音低频铺底与连续层，负责把 24 片连成一段
AudioMixerGroupsComponent组件分组音量混响层独立调，不与主声串音
DistanceAttenuationMode枚举INVERSE_SQUARED / FIXED柱阵半径 1.6 m 的听感校准（W2 真机调参）

另有两条备选通路，需要时再上：AudioResourceConfig(ambisonicsType)（全景声，用于环境层）与 SpatialAudioTrackExtension + SpatialAudioMode.OBJECT / AMBIENT（接第三方播放器）。

A.2模拟器能验什么、验不了什么

环节模拟器上的实际情况怎么办
空间音频听感验不了 —— 没有真实声场与 HRTF 听感只能靠 11.20 那次真机；这是止损线的唯一依据
声源指向性听不出「绕到柱背变闷」真机才能证明声音真的在那个位置，别的都替代不了

麦克风 / 实时采集无麦克风本方向只播放不采集，素材离线录好再打进包

方向光对自定义网格无效光照同样烘进贴图，别指望运行时打光

一句话判断

声之建筑是四方向里天花板最高、且唯一独占一条官方硬指标的一个。它的难处不在想法，在「能不能在真机上被听见」——所以整份方案的重量都压在 11.20 那次真机预约上。

放弃信号：11.22 仍无法在真机验证声源定位。此时切方向 D，不是因为 D 更好，而是因为拿不到的设备不会因为再等一周就来。

反过来说，只要 11.20 能戴上头显听到「绕到柱背声音变闷」，这个方向就没有理由再犹豫 —— 那时候真正要花力气的是把它做得更好看、更完整，而不是再比较方向。

本方案书的依据与边界

  • 已实测：官方 SDK 6.1 agent-vault 文档逐条核对；BOM 6.1.9 依赖解析与构建通过（包体 +80 KB）；四窗口工程与 42 个内核单测在位（commit 97bc6ad / 3b523a8）。竞品信息来自公开飞书文档，其创意方向与排期可能随对方进展变化。
  • 未实测：真机上的空间音频听感、stage.style 数字枚举、手势手感 —— 三项均已列入 W1–W2 验证任务与止损线。
  • 估算法：六维预估 91 为上限值，真机未验前按 85–88 折算；18–22 人日不含稳定性压测与打磨。
